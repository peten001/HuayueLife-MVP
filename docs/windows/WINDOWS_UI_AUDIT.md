# YunQiao Windows Native UI Audit

> 审计日期：2026-08-18
> 审计范围：`MainWindow`、`SettingsWindow`、WPF 样式、状态与错误呈现、触控和窗口适配
> 审计方式：依据当前 XAML/C# 源码进行静态审计；macOS 环境不伪造 WPF 运行截图
> UI 方法：Impeccable `Operate` 模式与 Native audit（可扫描、可操作、平台一致性优先）

## 平台一致性结论

当前 Native UI 能完成配置，但更像附加在 Cashier Web 上方的工程工具栏与参数表单，还没有达到门店 POS 的产品表达。最明显的问题不是功能缺失，而是 Native Shell 抢占主视觉、打印设置存在双入口、设置页暴露底层实现词汇，以及在 1366×768 高 DPI 环境下存在操作区被挤压的风险。

本轮应保留 Cashier Web、Bridge 协议和打印执行链，只精修 Windows Native Shell、打印设备窗口、状态和错误反馈。

## 系统性问题

1. **样式没有语义层**：颜色和控件尺寸由页面逐个决定，导致相同操作的状态、触控面积和焦点表现不一致。
2. **内部模型直接泄漏到 UI**：`WindowsSpooler`、`Lan`、`FRONT_DESK` 等内部值没有经过用户语言映射。
3. **正常与异常没有层级差异**：正常连接信息持续占位，而真正的 WebView 错误没有专属恢复控件。
4. **有效工作区未纳入窗口尺寸**：默认尺寸在 100% DPI 可用，但 125%/150% DPI 的低分辨率 POS 风险未被窗口逻辑吸收。

## 正向发现（保留）

- 设置窗口已经通过 `Owner` + `ShowDialog()` 以模态方式打开，能够阻止误操作底层 Cashier Web。
- 设置窗口已经使用 `CenterOwner` 和可调整大小窗口，方向正确。
- 主体使用 WPF 原生控件与 `ResourceDictionary` 可实现的能力，不需要引入第三方 UI 框架。
- 现有品牌绿、白色 Surface 和浅色背景与 YunQiao 视觉一致，可在不重做 Cashier Web 的前提下精修。
- 打印协议、设备传输和测试打印服务与 UI 分层清晰，本轮可只改显示映射与交互反馈。

## 本轮实施准则

1. Cashier Web 是主产品；Native Shell 只在状态异常或进入打印设备管理时被感知。
2. 不改变 `YunQiaoMerchantTerminal.postMessage(...)`、打印任务协议、transport 枚举或本地打印执行逻辑。
3. 触控优先：主要操作 44px，输入控件 40px，列表项 72px 以上，并提供明确焦点状态。
4. 1366×768 是最低重点视口；125%/150% DPI 通过工作区约束、可缩放窗口和滚动容器保证操作可达。
5. 用户文案只描述设备、连接方式、打印机、纸张、使用位置、状态和测试打印；技术信息保留在日志。
