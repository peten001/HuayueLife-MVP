# 收银新订单提醒｜上线与验收

范围：顾客新建的到店自取、商家配送订单，且订单仍为 `PENDING_ACCEPTANCE`。堂食和已接单订单不触发此提醒。

## 两层提醒

1. 收银页在前台：现有 10 秒订单轮询发现待接单后自动打开订单抽屉；若仍未处理，约 90 秒再次提醒。网络断开时无法保证即时提示，恢复后会重新读取待接单订单。
2. 手机主屏幕应用未打开：Web Push 由 API 的事务事件和重试队列发送给已授权设备，通知点击后打开对应自取/配送订单。推送不是接单，订单状态仍以服务端为准。

每个浏览器订阅绑定到当前商家员工；发送前重新确认员工和商家仍为 ACTIVE。员工停用或商家停业后，旧订阅不再接收订单提醒。

## 发布前条件

- 先部署 Prisma migration `20260919120000_cashier_order_web_push`，再启动新版 API；收银页发布最后进行。
- 通过受控密钥管理生成并保存一组长期稳定的 VAPID 公私钥，配置 API 的 `CASHIER_WEB_PUSH_VAPID_PUBLIC_KEY`、`CASHIER_WEB_PUSH_VAPID_PRIVATE_KEY`、`CASHIER_WEB_PUSH_VAPID_SUBJECT`（HTTPS URL 或 `mailto:`）。私钥只留在 API 环境，绝不写入 `VITE_` 变量、仓库、浏览器或日志。
- 确认收银页的 HTTPS Origin 在 API 精确 CORS 白名单内；`/cashier-push-sw.js` 必须返回真实 JavaScript、200、非 SPA HTML、非长期缓存。
- iPhone/iPad 需 iOS/iPadOS 16.4 或更高版本，先从 Safari 添加到主屏幕、从主屏幕打开，并在收银页点一次“开启提醒”授权。浏览器通知权限、系统通知设置、网络和省电策略均可能影响交付；不能承诺微信级的绝对送达。
- 新增生产配置、数据库迁移和手机权限验证前，不应把“后台已提醒”标记为已验收。

## 验收顺序

1. 使用测试商家/测试员工，在收银页确认“后台提醒已开启”；不要以仅打开网页或仅安装图标代替授权。
   开启成功后设置浮层直接收起，不应持续遮挡页面；之后可从账户菜单的“新订单提醒设置”重新查看状态或关闭提醒。
2. 保持收银页前台，新建一笔自取测试单和一笔配送测试单：只各弹一次新单抽屉，点击分别进入正确订单；堂食不触发。
3. 关闭主屏幕应用，再新建两类测试单：系统通知出现，锁屏可见，点击后进入正确商家对应订单。另一商家设备不应收到。
4. 断网/恢复与 API 重启后重复测试；检查 `cashier_push_events`、`cashier_push_deliveries` 中的处理/发送/失败状态。已接单订单不应再发后台推送。
5. 在手机退出登录，确认本机浏览器订阅被取消；联网时服务端同步删除，若同步失败则在推送端点失效后清理。重新登录需要重新开启或同步授权。

不能从后端“发送成功”推断手机用户已经看到通知；最终验收必须有手机实机的锁屏或通知中心证据。

推送事件与发送记录用于排查，超过 90 天的已处理/已终结记录由服务端分批清理；未终结记录不会因到期直接丢弃。
