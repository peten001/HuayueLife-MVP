## 1. 本轮结论

采用 **4 个主力技能 + 条件性设计工具 + 明确排除项**，全部相关技能登记，但不让多套默认风格、技术栈和自动发布流程同时控制项目。

- **Impeccable**：重构流程、用户任务、交互完整性、质量验收。
- **Finesse UI**：全后台统一视觉、布局密度、图表、表单与 Vue 界面落地。
- **Finesse Brief**：以既有产品为对象做只读审计，检查页面层级、数据来源和功能边界；不重新定义产品。
- **Emil Design Engineering**：按钮、弹层、提示、焦点与轻量反馈细节。
- **Stitch**：按需辅助规范提取、原型和设计稿管理，不接管生产技术栈。
- **design-taste-frontend / Stitch taste-design**：记录其适用范围和规则冲突，不把营销站风格或持续动画要求强加给餐饮后台。

这里的“调用”分为：主流程实际使用、满足条件后使用、仅作参考、不适用。没有把“已安装”“已读说明”“已调用工具”“已通过验收”混为一谈。

## 2. 已确认方向与不可改变项

### 页面方向

- 桌面：KiotViet 式紧凑顶部主导航，筛选与业务列表分区，详情保留来源上下文。
- 手机：常用底部导航 + 分组“更多”，列表、详情、筛选和操作面板独立适配。
- 品牌：YunQiao 绿色操作色，白 / 浅中性色主体，不复制 KiotViet 标识与蓝色主题。
- 首批：**工作台 → 指标明细 → 订单 / 结账详情**，先走通两端可点击原型，再扩展其余模块。
- 关注真实操作：数字是否可点击、跳到哪里、日期是否一致、如何返回、确认 / 取消 / 错误后发生什么，而不仅是静态截图。

### 硬边界

- 只重构现有商家后台 UI；不新增库存、HR 薪资、CRM、价目表、独立收款凭证等业务。
- 保留 Vue 3 + Vite + TypeScript + Pinia；不引入 React、Next.js、React Native、Shadcn React、React DOM。
- 不改变 API、权限、状态机、金额计算、营业日归属、图片缩略图链路、打印执行规则。
- 堂食仍按开台所属营业日；自取 / 配送仍按下单所属营业日；实际支付时间独立保留。作废、取消退空的财务排除不变。
- 不涉及独立 Cashier、MiniApp、平台后台、数据库或生产部署。共享样式改动须限制在商家后台作用域。
- 不改技能安装、不升级技能、不修复链接、不安装新依赖。此次不 commit、push、上线。
- 参考系统未验证 / 受限功能只列差异，不做可点击空入口。

## 6. 设计限制与冲突裁决

| 来源中的限制 / 默认 | YunQiao 的处理 |
| --- | --- |
| Finesse 默认不使用纯白 | 项目明确允许白卡片，保留 `#FFFFFF`；统一层级和对比度，不因通用偏好改品牌 |
| Finesse 的页面差异化 / 风格轮换 | 用于避免模板化，不在同一后台每页换配色、导航、字体；多页一致性优先 |
| Finesse 的手机专用固定框架 | 本产品同时支持桌面与手机，使用后台布局 + 响应式规则，不把桌面锁进 390 / 560px 手机框 |
| 通用防溢出规则建议全局裁切 | 先修容器收缩、列宽、长文本与按钮分配；不靠全局隐藏、横向滚动或 sticky 掩盖根因 |
| `taste-design` 要求持续微动画、列表错峰出现、默认弹簧 | 不用于本后台高频列表、金额、表格和切换。静止优先，仅保留有目的的短反馈；减少动态设置有效 |
| `taste-design` 默认大圆角、不对称布局、禁止等宽三列 / 768 以下强制全单列 | 不机械套用；金额比较、统计卡片与管理表格按任务决定结构，不为打破对称降低读数效率 |
| `taste-design` 强制字体 / 高密度数字全部等宽字体 | 优先已有字体与中越英覆盖，数字采用等宽数字特性；不为造型引入大字体包或牺牲越文、中文 |
| 多个技能都能写 `DESIGN.md` | 只维护一份经确认的商家后台视觉规范；Stitch 文件与 Finesse 模型只是其投影，不互相覆盖 |
| Finesse Brief 可定义数据实体、裁剪 / 扩展模块 | 仅审计已存在事实；发现缺能力写“暂不复刻”，不新建实体、接口或删除原有能力 |
| Emil 的长按删除、手势关闭示例 | 不替代既有删除 / 作废确认。草稿、危险动作和收款防误触机制保留；只改善呈现 |
| React / Motion / Shadcn 示例 | 只提取适用交互原理，使用 Vue 与现有依赖实现；不安装 React |
| 技能流程含云端上传 / 生成 / 发布 | “使用全部 UI Skills”不等于授权上传生产资料或发布。当前仅盘点，后续逐项遵守明确的素材与目标边界 |

规则优先级：**用户本次范围与项目 AGENTS → 已核实业务事实 → 经确认的商家后台产品 / 设计规范 → 各技能被分配的专项规则 → 参考产品外观**。

## 8. 八模块分工与检查重点

| 模块 | 主要专项 | 必查操作 |
| --- | --- | --- |
| 工作台 | Finesse 数据布局 + Impeccable 任务顺序 | 待办、快捷入口、数据下钻、刷新状态 |
| 经营分析 | Finesse 图表 / 指标 + Brief 数据来源审计 | 日期 → 同口径明细 → 返回；多日不能错误跳今日，不能把结账笔数当原订单数 |
| 订单 | Finesse 表格 / 详情 + Emil 弹层 + Impeccable 边界 | 筛选、原单 / 结账详情、作废确认、已作废记录、返回原日期 / 页码 / 位置 |
| 菜品 | Finesse 密度 / 响应式 + Impeccable 长文本 | 多语言、紧凑数字、图片、状态、分类、编辑 / 删除始终可见；单位与缩略图语义不变 |
| 桌台 | Finesse 状态展示 + Emil 更多面板 | 长编号不挤时间、启用状态不等于用餐状态、账单与桌码入口、返回 |
| 设置 | Finesse 表单 + Impeccable 文案 / 边界 | 只读资料与可编辑配置区分、营业时段、保存 / 取消、输入错误 |
| 员工账号 | Impeccable 权限呈现 + Finesse 表单 | OWNER / MANAGER / STAFF、禁用 / 无权限说明、重置密码 / 停用确认；不新增 HR |
| 打印中心 | Finesse 配置 / 预览 + Impeccable 状态可读性 | 开通 / 在线 / 已打印分开、配置 / 记录 / 帮助入口；不更改协议或实际打印规则 |

### 统一验收门槛

- 正式目标宽度 **1440 / 1280 / 1024 / 768 / 390**，辅以窄屏压力测试；真实中 / 越 / 英长文本与 VND 大金额。
- 桌面菜品列表 1440 / 1280 / 1024 无需横向滚动即可看到编辑 / 删除；窄屏主内容和弹层不横向溢出。
- 加载、空数据、失败、禁用、选中、悬停、焦点、按下等组件状态；权限、错误数据和长内容页面状态分别覆盖。
- 手机安全区、底部按钮 / 导航不遮挡、软键盘、滚动容器、弹层关闭和返回位置。
- 鼠标、触控、键盘、可见焦点、语义标签、对比度与减少动态；手机点击区域保持易操作。
- 不新增数据轮询、逐日请求扇出、大动画或图片负载；检查布局稳定和操作响应。
- 已有 API 请求、角色 / 能力限制、营业日、作废 / 取消排除、结账金额和打印语义回归。
- 改动后按项目要求运行类型检查、构建与相应交互 / 合同测试；生产业务写操作不作为 UI 测试数据。
- 不能用设计稿、静态 HTML、构建通过或工具状态代替真实交互 / 真机验收。
