重构验收：保留查询营业日、状态、类型、搜索词、正常 / 作废模式、页码及滚动位置；浏览器后退和界面返回均要覆盖。这里只保存 UI 上下文，不更改查询业务含义。

### 5.2 桌台账单长编号与开始时间重叠（网页实测）

当前桌台账单弹层顶部把桌号、显示名、会话编号、开始时间、状态排在同一行。真实长会话编号压到开始时间。

重构验收：编号允许独立占行、换行或安全截断查看完整值；信息列必须允许收缩；手机使用标签值分组。不得只用 `overflow:hidden` 隐藏重要信息。

### 5.3 数据入口不统一（界面 + 代码）

经营分析的主要指标是展示卡片；已有“查看详情”主要用于经营简报，并非资金明细。订单已有结账明细弹层，但与普通订单详情是两个不同对象。

不能把“结账笔数”指向普通订单数量，也不能把“净营业额”指向未完成订单金额合计。已完成结账明细、订单原单、支付金额三个概念必须各自明确。

### 5.4 视觉层级不统一（网页观察）

工作台有大标题、较大的摘要和快捷入口；订单 / 菜品 / 设置 / 打印页面采用不同密度、按钮和分组方式。侧栏占用明显，部分页面首屏给业务列表留下的空间较小；店铺只读资料与经营设置的优先级需要重新组织。

本轮未执行完整断点验收，不能宣称所有页面均无横向溢出。

## 8. 建议方向（待确认，不是已实施）

**KiotViet 的操作结构 + YunQiao 的品牌与业务。**

- 桌面：建议采用紧凑的顶部主导航，列表页用轻量筛选区 + 宽主内容；详情保留列表上下文，视信息量采用行内展开 / 侧层 / 原有独立页。不强行让每个页面都套同一种弹窗。
- 手机：保留现有常用导航的业务入口，采用独立移动结构；首页摘要、列表单列、详情逐层进入、筛选分组、更多动作面板，底部主操作避开导航与安全区。不是把桌面表格缩小。
- 颜色：保留 YunQiao 绿色为操作色，白 / 浅灰为大面积底色；去掉大面积深墨绿、无意义的重阴影和重复卡片嵌套。不复制 KiotViet 品牌标识 / 蓝色主题。
