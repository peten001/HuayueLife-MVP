## 1. 用户新证据与真正要改的地方

用户反馈电脑 V2.1 显得空、粗糙，并提供 KiotViet 网页首屏与下滚截图，说明“更像把经营分析放在首页，再点击进入其他”。

截图可见的结构：顶部主导航；主内容上方三组包含次级信息的经营卡片；中部营业额 / 客流图；下方菜单表现；右侧最近活动与参考产品的商业入口。截图中的箭头、页签、日期控件证明存在视觉入口，不单凭静态图宣称每条跳转已操作验证。已有实际交互证据继续以首轮调研记录为准。

此前问题不只是留白：把“总览”做成轻量摘要，再另设“经营分析”，让首页缺少完整内容，也把经营查看拆成重复入口。**新版直接以现有经营分析为首页主体，再改布局、信息分组和点击层级。**

## 2. 本版空间与交互方案

### 顶部：短导航，不占两层大面积空白

电脑顶部为一条紧凑的品牌 / 主导航 / 门店与账号行：

**YunQiao　总览 / 订单 / 菜品 / 桌台 / 设置**

总览就是分析首页，不再并排出现内容重复的“总览”和“经营分析”两个一级入口。门店名称只读显示。设置内保留已有经营设置、员工账号、打印中心等分组。

### 首页：主分析区 + 辅助明细栏

主区域约占四分之三，右侧约四分之一，不再把同一张简单折线图拉满整行。

| 位置 | 内容 | 作用 |
| --- | --- | --- |
| 页头 | 经营总览、统一日期 / 营业日、刷新 | 明确全页查询周期 |
| 主区第一行 | 营业收入（净额、折扣、抹零）、结账概况（笔数、客单价）、收款构成（现金 / 转账 / 历史未记录） | 一组卡片回答一类经营问题，不只是空盒子里的大数字 |
| 主区第二行 | 营业额走势、结账笔数走势并列 | 同一周期比较金额与交易频次；不把结账数标成客流 |
| 主区下方 | 菜品排行，后续承接已有时段与更深入分析内容 | 桌面显示完整行、销量与金额，不缩成三个大图标 |
| 右侧上方 | 已有经营简报，允许展开 | 承接现有真实数据生成的说明，不新增聊天或智能代理功能 |
| 右侧中部 | 最近结账 → 结账详情 → 关联原单 | 明细入口，不是接单队列，也不伪造员工操作日志 |
| 右侧下部 | 时段分布 / 查看更完整时段数据 | 使用已有时间分布数据，不增加无来源指标 |

密度来自更完整的已有业务内容与明确主次，不靠微小字体、粗边框或十几种装饰性控件填满屏幕。图稿使用较小的图标、紧凑表头、真实行结构和右对齐数字。

## 3. 配色不重选，两端结构按最新确认

- 保持已确认经营分析色系：浅灰绿 `#F1F5F1`、近白 `#FBFDFB`、浅分组 `#EDF3EE`、绿色 `#2F9E44` / `#1F7835`，少量既有蓝 / 琥珀辅助色。
- 不复制 KiotViet 的蓝色品牌导航，不回到旧深绿侧栏。
- 手机最新采用用户明确指定的：首页（经营分析）/ 菜品 / 订单 / 结账 / 更多。用户已澄清“结账”是查看结账与收款记录，不执行收银操作。此前四栏结构不再保留；详见 V2.3 手机稿。
- 两端共享数据组件和经营口径，按屏幕分别组织；不把电脑信息密度硬塞进手机。

## 4. 数据与入口约束

- 分析首页直接复用现有 `getMerchantAnalytics` 返回的概览、资金、趋势、结账笔数、时段、菜品排行；不为每块图表重复请求或新增接口。
- “最近结账”复用现有结账列表 / 详情；目前结账接口按单营业日查询。选近 7 天 / 近 30 天时，该栏应改为已有趋势的“按营业日查看结账”，先选一天再进入明细，不能把最后一天的记录冒充整个周期，也不逐日扇出请求。
- 全页分析卡片与图表共用选中周期；卡片若表示当前营业日而图表是近 7 天，必须分别清楚标明，不允许隐含混用。
- 原 `/business-analytics` 入口、手机入口、收藏链接与权限不能因为桌面导航合并而失效；具体路由兼容在实施时处理，不盲目全量重定向。
- 当前 OWNER / MANAGER 可访问完整分析；STAFF 不因首页合并而获得分析权限或发起无权分析请求。其首页继续使用已授权的数据和导航，不新增财务可见性。
- 堂食属于开台营业日，自取 / 配送属于下单营业日；作废、取消退空排除规则及实际支付时间保留。
- 不新增接单或履约操作。原单 / 作废等管理能力照旧保留，接单统一由收银端执行。

## 5. 不照搬的参考内容

KiotViet 截图里的客流、桌台覆盖率、客户数、库存活动、多门店、贷款、促销和支付服务等，不能因为有空位就填入 YunQiao。只采用已存在的数据与入口；暂未核实对应字段或服务的内容不在正式首页放假数据、假按钮。

本版用“结账笔数”对应已有统计，用“最近结账”提供实际明细入口；不把它们冒充客流或完整员工操作审计。
