# YunQiao 商家后台 V2.1：经营管理定位审核稿

状态更新：**本稿是历史版本，非实施回执。** 电脑端改按 [V2.2：首页即经营分析](20260905-v22-desktop-analytics-home.md) 审核。手机外观曾获认可，但用户后续明确要求五栏导航与分析首页，现以 [V2.3 手机结构](20260905-v23-mobile-navigation.md) 为准；不再执行 V2.1 四栏导航。

## 1. 最新决定与替代关系

本稿同时落实用户最后三条指令：

1. 商家后台不再保留接单部分，接单统一由独立收银端执行。
2. 重构以 KiotViet 为主要参照，旧 YunQiao 布局不作为限制；重新规划一版由用户审核。
3. **配色以现有 YunQiao「经营分析」页为基础**，再结合 KiotViet 全面优化。此条覆盖中途提出的纯灰、低饱和灰绿方案。

前三稿中的接单队列、待办优先和大绿色导航不再延续。此前“助手自行选定并开发”的授权不用于跳过本次审核。

## 2. 页面目标与使用场景

老板和店长在电脑上核对营业结果、查找订单与结账记录、维护菜品和设置；在手机主屏幕独立窗口中快速查看、筛选、进入详情和返回。后台是经营管理入口，不是第二个收银台。

核心路径：**看结果 → 选营业日或条件 → 查明细 → 进入原记录 → 返回原位置**。不会因为退出详情而跳回今日，也不会把结账笔数错误映射为原订单数量。

## 3. 视觉依据：继承经营分析配色，而非继承旧页面骨架

已读取 `apps/merchant-admin/src/pages/BusinessAnalyticsPage.vue` 的真实颜色变量。以下是参考事实，不是猜测的截图取色：

| 用途 | 当前经营分析颜色 | 新版使用方式 |
| --- | --- | --- |
| 页面底色 | `#F1F5F1` | 全后台浅灰绿底，保持轻量 |
| 内容表面 | `#FBFDFB` | 列表、指标、详情与表单的近白底 |
| 次级分组 | `#EDF3EE` | 表头、轻量分组和次要区域 |
| 边界 | `#DFE8E1` | 轻分隔，不用粗边框切割每块内容 |
| 正文 / 次级文字 | `#183426` / `#5F6D65` | 金额与订单号保持深色清晰，不为“淡”牺牲对比度 |
| 主色 / 强调 / 浅底 | `#2F9E44` / `#1F7835` / `#E5F4E8` | 当前入口、少量按钮、选中态；不铺成整条深绿导航或侧栏 |
| 辅助色 | 蓝、琥珀、紫的小面积色组 | 沿用分析页指标 / 图表的分类能力，不把每一行都涂色 |

设计变化：去掉深色大侧栏；顶部白底导航，绿色仅标当前入口。减少超大标题、大胶囊按钮和重复卡片嵌套。经营分析的轻卡片风格可以保留，但表格、表单和资料页按各自任务重新组织，不能全部复制五张指标卡。

## 4. 两端总体结构

### 电脑

顶部第一行：YunQiao、当前门店、语言、账号。第二行：**总览 / 经营分析 / 订单 / 菜品 / 桌台 / 设置**。

“设置”分组承接店铺资料与经营设置、员工账号、打印中心；这些模块仍保留真实入口，不是删除功能。所有入口继续按现有角色和能力开关展示。

内容布局按任务分三类：

- 经营页：指标摘要、趋势、资金 / 排行，逐层进入同口径明细。
- 记录页：紧凑搜索 / 筛选 + 宽列表；详情展开或独立进入，但保留列表上下文。
- 设置页：左侧分组目录 + 右侧表单 / 配置；打印设置保留配置与预览并列。

### 手机与主屏幕模式

常用底部导航拟为 **总览 / 订单 / 分析 / 更多**，不是桌面菜单缩小。角色无权访问的入口不显示，也不放置假入口。

“更多”按业务管理、店铺与设备、账号分组。详情、编辑、筛选采用独立层级；二级页突出应用内返回，必要时收起主导航，为内容和保存区让出空间。

安全区、返回、软键盘、未保存退出、固定保存按钮与滚动恢复均作为正式验收项。画面不绘制假的 iPhone 状态栏或浏览器工具栏。

## 5. 八模块如何重构

| 模块 | 新版结构与重点操作 | 不扩展的边界 |
| --- | --- | --- |
| 总览（原工作台） | 营业日 → 净营业额 / 结账笔数 / 客单价 → 营业趋势、资金概览 → 最近结账与菜品销量；指标给出正确的明细入口 | 不再展示待接单面板、接单按钮、新单语音开关；没有接单任务队列 |
| 经营分析 | 作为色彩与组件基准；统一日期区；主要指标优先，资金、趋势、时段、菜品排行分层；已有简报 / 建议保留但弱化抢占 | 不删已有分析数据，不增加无依据的利润、成本或经营预测 |
| 订单 | 订单记录 / 结账记录 / 已作废清晰分开；搜索、营业日、状态、类型筛选；电脑紧凑行，手机信息行；关联原单可进入 | 不做新单处理台；作废、审计与管理能力不因移除接单而一起删除 |
| 菜品 | 电脑分类筛选 + 固定宽度分配表格；手机图文列表 → 资料 → 编辑；分类编辑保持已有能力 | 名称多语言、单位、缩略图、上下架、售罄与删除业务不改；桌面编辑 / 删除直接可见 |
| 桌台 | 桌台资料列表 → 当前会话或已有账单；基础编辑、桌码与危险操作分层 | 不新增 KiotViet 的桌台分区功能；启用状态与用餐状态分开；不重建收银开台和结账流程，不改变换码规则 |
| 店铺设置 | 店铺资料、营业时间、配送等按现有字段分组；手机从目录进入子页；只读资料清楚标识 | 不新增统计归属开关，不开放平台维护字段 |
| 员工账号 | 紧凑账号列表 → 角色 / 状态详情 → 编辑；停用、重置密码有确认 | 仍是账号权限管理，不新增 HR / 工资 / 考勤 |
| 打印中心 | 打印机、自动打印、小票设置、记录、终端与帮助统一导航；状态和预览各自清晰 | 保留已有模板、协议、设备状态与执行规则，不把“开通”当成“已打印” |

### 接单边界必须检查所有入口

实施时要核对总览、订单列表、订单详情以及共享新单提醒，不能只从首页隐藏一块面板，其他入口仍能接单。需要退出后台的是接单操作区与其提醒，不是删除历史订单、删除状态信息、修改后端状态机或重新实现收银能力。

原首页还混有开始制作、完成制作、配送、完成等现场履约动作。本稿不在管理总览中呈现这些动作；它们在其他后台页面中的最终呈现须做动作清单核对，不能把用户关于“接单”的要求无条件扩大为删除收款、取消、作废、打印或聊天等全部既有能力。审批本稿也不授权改收银源码或权限规则。

## 6. 不只看布局：具体点击结果

| 点击 | 目标 | 返回规则 |
| --- | --- | --- |
| 单日净营业额 / 结账笔数 | 同营业日的有效结账记录 → 结账详情 | 保留来源页、营业日、筛选、页码与位置 |
| 多日总额 | 已有趋势中的逐日明细 → 选一天 → 当天结账记录 | 不跳到今日，不用逐日请求拼接新接口 |
| 结账详情的关联订单 | 现有原订单详情 | 返回该笔结账详情，不丢失原列表 |
| 图表 | 对应已有粒度的数据说明；有正确日级目标才进入明细 | 小时数据不能伪装成接口不支持的精确订单筛选 |
| 现金 / 转账 | 展示既有资金分组与口径说明 | 不虚构支付凭证服务，当前草图金额不是凭证按钮 |
| 菜品行 | 资料 / 现有编辑能力；更多动作放次级区域 | 返回原分类、搜索与位置 |
| 筛选 | 手机分组筛选层，确认应用后更新列表 | 关闭不应用，原条件不变 |
| 详情“更多” | 仅当前对象实际支持且当前角色有权使用的管理动作 | 危险操作保留原有校验、确认和结果反馈 |

这些是设计目标，不是已经实现或验证过的跳转。前端真实接口是否提供该字段、当前角色是否可访问，仍须逐项对应现有合同。

## 7. 始终不变的业务与实施约束

- 堂食属于开台营业日，自取 / 配送属于下单营业日；支付时间独立显示。
- 作废、取消退空等财务排除规则保持；原单与结账单不混算。
- Vue 3 + Vite + TypeScript + Pinia；不更换技术栈、API、权限、状态机、数据库或打印协议。
- 不新增库存、采购、CRM、工资、独立支付凭证、税务、多分店等参考能力；只记差异，不放假入口。
- KiotViet 已见的桌台分区不能直接照搬：当前桌台页未找到分区管理实现，本稿只重组已有桌台资料和账单入口，不新增分区实体或编辑能力。门店名称只读显示，不画成多门店切换控件。
- 先本地隔离验收，不以生产写操作测试；不 commit、push 或上线。
- 目标宽度 1440 / 1280 / 1024 / 768 / 390，覆盖长中越英文本、大金额、弹层与触控。

审核重点只有三个：

1. **定位**：后台看经营和做管理，接单留在收银，是否符合使用习惯。
2. **视觉**：经营分析的浅灰绿 / 白色 / 小面积绿色是否适合作为全后台基准。
3. **操作结构**：KiotViet 式顶栏、手机分层、数据到明细和原路返回是否成立。

本轮使用 Impeccable 的规划 / 审核停点与 Finesse 的后台结构原则；按用户“重新规划一个版本”的要求不再强制生成三种方向。图稿使用内置图片生成，仅为视觉审核。Emil 的触控、焦点和反馈规则留在获批后的实现 / 验证阶段，不把静态图当作交互已通过。
