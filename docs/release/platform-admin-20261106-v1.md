# YunQiao 平台后台重构发布

- 用户授权：提交、推送并上线；必须保持现有平台经营总开关关闭及各商家原有配置。
- 版本：`platform-admin-20261106-v1`。
- 当前阶段：已核对生产配置，准备候选与备份；下文结果以最终验收记录为准。

## 发布范围和不变条件

发布平台后台及其配套 API；保留商家端现有视觉、收银、KDS、小程序运行版本。数据库只增加评价审核原因的两个可空字段及对应迁移记录，不运行种子或商家／标签／能力批量改写。

生产公开配置已只读核对 `platformOrderingEnabled=false`。发布前、候选验证、切换前后均检查该状态；禁止通过开启生产开关来验收。商家可见性、认领、独立经营能力、内容配置、打印、KDS、原环境及上传文件分别留存基线与哈希核对。

当前生产 API 基线是 `merchant-discovery-20261105-v1`，运行依赖保持 `delivery-coordinate-response-20261025-v1`。共享公开商家模块保留线上已运行但尚未纳入 Git 的发现排序及展示逻辑；当前编译文件与线上对比仅三处取消数量截断的差异。该源文件及对应回归一同纳入本次提交，防止重构回退既有线上行为。工作区其余小程序、共享坐标及相关文档改动保留且不进入本次发布。

## 发布顺序

1. 提交本次源码，用确切提交构建候选并执行类型、构建及业务验证。
2. 备份数据库、当前 API／Linux 依赖、现有后台目录、原指针和配置；校验归档。
3. 在隔离数据库验证新增迁移与真实 API 流程；生产只允许预期的新增迁移。
4. 候选沿用原 Linux 依赖；只生成适配新增字段的 Prisma Client，不升级其他依赖。保留当前线上 API 的其余编译文件。
5. 验证生产总开关仍关闭后执行新增迁移，进行仅回环地址、无定时副作用的候选启动核对。
6. 原子切换 API／依赖指针并重启原进程；健康、鉴权及只读业务查询通过后切换平台后台。旧哈希静态资源保留，原上传目录不参与替换。
7. 服务器及外网分别校验资源与接口、经营关闭状态和受保护配置；发布结果、源码提交和回退位置补入本记录。

接入层仅为 20MB 照片与 50MB 导入包增加 multipart 体积余量；其他代理目的地、TLS、环境及服务设置保持。

## 回退原则

遇到非预期变化时恢复原 API／依赖／后台指针及必要的 Nginx 配置，不回滚营业数据库、不覆盖发布后产生的真实业务数据。新增可空原因字段保留兼容旧版；不通过重置开关、商家状态或账号来“修复”验收结果。

## 本地验证基线

全仓类型与构建、1,399 项 API 测试、后台回归及 22 个页面／15 条操作流程通过；平台总控补充 28 项相关回归通过。源代码浏览器验收使用隔离样本，生产联调及迁移的实际结果将在发布完成后记录。
