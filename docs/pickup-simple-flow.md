# 打包自取恢复普通流程

日期：2026-10-21。状态：本地完成，未提交、推送、部署或上传小程序。

用户要求：恢复之前的到店自取流程，只将顾客入口放在“预约到店 → 打包自取”。

## 顾客下单与商家处理

顾客：商家详情 → 预约到店 → 打包自取 → 原菜单 → 购物车 → 普通结算 → 自取订单详情。普通结算填写联系人、电话及备注，不再出现预约取餐时间或预约确认表单；创建普通 PICKUP 订单，不发送 reservation 或 scheduledFor。沿用原自取营业状态、经营能力、价格校验、取餐码、订单聊天、取消及线下付款流程。

商家：待接单 → 接单后直接制作中 → 制作完成／KDS 出餐后待取餐 → 核对取餐码、收款及确认取餐 → 已完成／订单记录。一次接单沿用原 accept＋start-preparing 操作及失败恢复机制，不再增加单独开始制作节点。收银电脑／手机筛选统一为全部、待接单、制作中、待取餐；删除待备餐、该备餐、30 分钟提醒、预约改约操作及对应样式和文案。

## 历史与其他业务

- 旧预约自取链接转到普通自取菜单；旧菜单／商品链接里的 reservation 参数不再给自取启用预约。旧缓存购物车移除自取预约标记，已有餐品保留，正常进入结算。
- 历史 isReservation=true 自取订单保留原标记与取餐时间，已接单状态在收银按制作中显示，进度与普通自取一致。接单或开始制作时清除历史待回复的取餐时间提议，不修改原 scheduledFor；旧提议回复在状态变化后仍受服务端并发校验。
- 旧 DUE／ACCEPTED 自取筛选书签统一到 PREPARING；旧预约提醒书签进入现行自取制作队列。预约页与提醒不再统计自取备餐，打包自取仍只走自取通道。
- 接单立即触发原打印意图及 KDS 同步；历史已接单自取在开始制作时复用原接单日志，打印继续使用同一事件键，已有意图不重复。KDS 不再因预约标记延迟已接单自取任务，取餐码及历史取餐时间仍可显示。没有数据库迁移或订单历史清理。
- 用餐预约仍先订座、商家确认后选菜，到店入座再进入桌账；不改变用餐预约的时间、桌台、聊天或厨房规则。配送和普通扫码堂食继续原流程。

## 发布范围

需要同步 API 与收银；小程序由用户重新上传体验版／发布。KDS 静态页和后台页面无改动，无数据库迁移或依赖升级。后端恢复已接单自取报厨后，历史预约自取的远期时间也只作参考，不再自动等待到约定时间前 30 分钟。当前生产保持上一次已发布版本。
