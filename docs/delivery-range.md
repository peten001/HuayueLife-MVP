## 当前规则

- 商家配送使用商家资料中原始 WGS84 坐标和顾客收餐点 WGS84 坐标，沿用原有球面直线距离计算，不改成道路里程，不新增坐标转换。
- 距离小于或等于 `deliveryRadiusKm` 时允许创建，按商家设置收取配送费；大于半径直接拒绝。不先四舍五入距离，边界本身包含在范围内。
- `0 km` 是零半径，仅允许坐标相同的点，不表示不限距离。负数或无效配置拒绝配送预览和创建，并提示暂时无法校验。
- 配送必须有一对有效收餐坐标，缺少任一项、非有限数字、越界或 `(0, 0)` 不允许跳过距离校验。文字地址不完整但坐标在范围内时，沿用补充地址／电话确认的原有流程。
- 堂食、自取不进入配送距离规则，配送费为零。既有订单履约不受新订单校验影响，已成功创建订单的同一幂等请求仍返回原订单。

## 小程序与服务端

结算页继续使用现有地址卡、地图按钮、坐标行和底部提交按钮。地址提示优先显示“当前地址超出商家配送范围，无法下单，请重新选择地址”，同时禁用提交；不提供超距“继续提交”弹窗。未选有效收餐点时提示先地图选点。重新选到范围内后，提示和按钮即时恢复；继续使用微信原生选址，支持手动补充详细地址。

小程序构建请求及实际提交入口都检查已知的超距状态。配送下单前预览失败时停止本次提交，不再忽略错误后调用创建；包含服务端半径已变化或网络校验失败的情况。文字和错误映射同步中文、越南语和英语。门店信息暂未加载时，服务端仍负责最终判断。

`OrdersService.preview` 和 `create` 均调用实际 `validateAndPrice`／`resolveDeliveryPricing`；服务端按当次读取的商家配置校验，超距返回 HTTP 400。未选点和无效配置也返回 400。拒绝发生在订单／状态日志创建、购物车结算、推送及打印之前，保留购物车供顾客改址重试；旧版客户端不能通过忽略提示、直接调用创建或省略坐标绕过规则。
