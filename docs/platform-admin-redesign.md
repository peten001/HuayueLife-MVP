## 导航与逐页设计

左栏按工作任务分组，所有分组始终展开，子入口全部可见，不显示分组折叠箭头；屏幕高度不足时侧栏纵向滚动。品牌区只保留原绿色 Logo 与 YunQiao。页头统一放标题、作用域和一个主要操作；界面语言入口放在全局顶栏，默认中文，可切换越南文或英文。列表统一支持搜索、已生效的筛选标签、服务端分页和返回时恢复条件。商家、订单、用户等记录在右侧快速查看，完整编辑从明确入口进入专页，返回时恢复筛选、页码和位置。详情能从订单、商家和用户之间跳转。本轮按电脑后台设计，覆盖常见电脑宽度，不新增手机后台重构任务。

批量选择已确认：先选本页，提供带数量的「选择全部筛选结果」入口，只有明确点击后才扩展范围。筛选条件变化后重新选择，执行时固定记录集合，成功／失败分别统计，重试仅针对失败记录。

## 图表与交互规格

- **阅读顺序。** 运营总览回答「今天哪里需要处理」，营业分析回答「在哪个时间和范围内发生了什么」。总览首屏留给待办与四个关键指标，分析页首屏保留筛选、核心数字和可读的主趋势。
- **默认周期（已确认）。** 运营总览看今天，营业分析默认近 7 天，并与前 7 天比较。手动选择后的结果和明细跳转共用已生效范围，返回列表保留条件。含今天的数据标明进行中，不把尚未结束的日期描述为完整一天。
- **图形。** 订单量与订单额使用共用日期轴的指标切换，避免两个单位挤在同一刻度。状态和渠道用有标签的水平条，商家排行用可按单量或金额切换的表，城市比较同时展示笔数和 VND。比较线以灰色虚线区分，状态用文字和颜色共同表示。
- **读数。** 坐标轴注明单位，悬停或键盘聚焦显示精确值和日期。完整数值可从表格读取，缺数据、零值、接口错误分别呈现。点击图形传入已生效的条件，打开对应明细。
- **金额与时间（已确认）。** 运营日期统一使用越南时间。统计排除作废单，下单数包含取消单并单列取消数量；主指标为已完成订单额，进行中／取消订单额分别列出。金额按订单记录计算，不标为实收或结算收入。图表刻度用百万 ₫，指标和明细用完整金额；悬停、明细和导出保留原精度。状态比例注明分母。校验同范围内总览、分析、订单明细的统计结果。
- **视觉。** 已选定雾白底、白色内容区、蓝色信息与主操作，紫／青等辅助色按用途分工；保留色彩浓度和局部细节微调，Logo 维持原绿色。列表行高、表头、时间、金额和状态样式统一，金额右对齐。桌面保持适中表格密度，按中越英长文本调整字段宽度与换行。使用本地商家缩略图、内容媒体及对应预览，其余页面用清晰的文字与图表组织信息。
- **组件。** 从现有 Chart.js 依赖做后台通用趋势图和分布图。共用表格工具栏、日期范围、状态标签、详情抽屉、上传队列、反馈与确认层。用独立的平台样式作用域避免覆盖商家端。

## 接口与数据配套

- 商家、订单、用户及关联选择器统一支持服务端查询和分页。当前商家列表先取全部商家再在浏览器过滤，分析接口先读取选中期间的原始订单再计算汇总，重构时相应改为数据库聚合及范围校验。 [商家查询](../apps/api/src/modules/platform/platform-merchants.service.ts#L395) · [分析查询](../apps/api/src/modules/platform/platform-analytics.service.ts#L35)
- 资料草稿和发布围绕同一 Merchant ID 实现。已确认草稿只需店名＋城市，缺定位使用明确的空值，需调整当前必填字段和存储语义。首次公开与对外更新按行业清单校验，草稿媒体不能在上传时提前改写当前生效展示。公共必备资料为店名、城市、行业、联系人和电话、地址与精确定位、封面、介绍、营业时间；餐饮补菜单或菜品，酒店补房型，服务商家补服务项目。对外店名、地址、介绍的中文＋越南文齐全，英文选填。现有 `computeProfileCompletion` 的 9 项完整度不能替代新的发布契约。
- 已有商家过渡方式已确认：保留当前展示状态，资料不齐者列入待完善清单，显示缺项与编辑入口，不按新清单批量隐藏。首次公开与后续「保存并更新」执行新校验，另存草稿继续保留旧公开版本；更新成功或主动隐藏后才改变当前展示。迁移、旧链接、公开接口和跨端兼容一起验证。
- 上传队列固定目标商家，部分失败可重试。批量导入使用服务端任务标识与行标识防止重复新增。保存版本用于发现两名运营同时编辑的冲突，变更成功的分区明确反馈。
- 现有平台设置写接口只支持全局经营开关。概念图中的名称、城市、默认语言编辑和全站操作记录属于提案新增能力，需要真实配置读写、校验及权限支持。运营时区显示为只读的 `Asia/Ho_Chi_Minh`，所有日期筛选依同一时区处理。
- 用户已确认本轮统一使用平台管理员权限，沿用 PLATFORM_ADMIN 身份，不新增管理员／运营／审核／只读角色或对应权限配置页面。平台账号范围、既有身份验证与接口校验一起验收，操作记录保留执行人和影响结果。

## 图片和标签规则

- **图片（最新确认）。** 门店外观、环境、菜品和商品图库张数放开，新增、编辑、导入采用相同规则。单张上传源文件最多20MB，上传后统一自动优化，清晰度以现有平台照片为基准，服务器不永久保留源文件；此前「可切换原图免压缩存储」方案结束。支持横图、竖图和方图，封面裁切单独预览。显示处理进度、失败原因和单张重试。只保存优化展示图及列表小图，不反复对已优化文件再次有损编码。优化结果不满足显示质量时不盲目强压到固定体积。旧图沿用现有URL、显隐与顺序，不因本次上传规则批量删除既有文件。前端、平台上传接口、商家图片接口、ZIP逐图校验与服务接入层同步放宽当前5MB入口限制。 [当前图库约定](merchant-gallery.md) · [当前图片接口](../apps/api/src/modules/platform/platform-merchants.controller.ts#L150)

当前图片实现已核对：[优化器](../apps/api/src/common/utils/merchant-display-image.ts) 默认WebP长边1440／质量82，体积软目标320KiB，必要时尝试质量78或长边1280；列表图最长480／质量76。比例保持、不放大小图。[平台上传服务](../apps/api/src/modules/platform/platform-uploads.service.ts) 已只写优化展示图与小图，源文件用于内存处理与内容哈希，当前校验仍为5MB。重构以这套既有观感与生成方式为基准；增加大源图后做相同场景下的清晰度对照，不能把“视觉相近”表述为数学无损。临时文件如有使用，完成或失败后清理；不新增原图永久存储。
- **标签。** 解除菜系、场景每类四个的后台绑定上限和 API 上限，同时处理公开接口的截断。用户已确认公共标签改名同步所有关联商家，并显示影响数量及关联商家入口；保留原标签 ID 与内部业务标识，不要求商家重新绑定。小程序详情可展开完整标签，首页卡片按展示位规则选择；本轮不重新设计其他端视觉。停用标签从公开展示移出，同时保留关联记录。 [前端选取](../apps/merchant-admin/src/pages/PlatformMerchantDetailPage.vue#L493) · [写入校验](../apps/api/src/modules/platform/platform-merchants.service.ts#L1799) · [公开输出](../apps/api/src/modules/public-merchants/public-merchants.service.ts#L761)

## 实施批次与验收

1. **全局框架与数据。** 建好导航、共用交互组件和筛选地址规则。交付登录、总览、营业数据，先修查询条件和指标的歧义。验收能从告警到同范围明细，零值正确显示、失败可恢复，常见电脑宽度下所有入口可达、中越英长文本可读。
2. **商家与内容。** 交付商家列表、草稿、导入、图库、分类、标签、首页推荐、行业和回收站。验收店名＋城市可保存草稿，草稿不公开，按行业清单与中越文齐全后可展示；保存并更新生效，另存草稿保留旧展示。20MB图片上传后统一优化，仅保存展示图与小图，原件不永久落盘；单类50张图可部分重试，旧图／模板可读，单店可绑定超过4个菜系或场景标签。重复导入默认跳过待核对。现有资料不齐门店保留展示，回收站恢复后隐藏，不在迁移中批量隐藏或公开门店。
3. **交易、用户与系统。** 完成订单、评价、用户、设置与诊断。验收商家→订单→用户联查、评价审核结果与人工记录、总开关影响和失败处理、三语界面和权限边界。
4. **联测与切换。** 用脱敏样本覆盖常态、空态、错误、中越英长文本、常见电脑宽度、部分失败和重复提交。逐条比对新旧路线及既有权限；共用接口改动需验证现有端兼容。跨模块执行全仓类型检查与构建，实际涉及小程序接口／展示的变更按仓库要求执行微信构建及对应回归，不另行重构小程序。按模块发布，旧路径兼容并保留可回退版本；正式开发、提交与发布以用户后续明确指令为准。
