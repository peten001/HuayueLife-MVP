# YunQiao Merchant Admin

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

餐厅老板、店长与授权员工，在电脑浏览器或手机网页中处理经营管理。用户明确以 iPhone「添加到主屏幕」后的独立窗口使用手机后台；它仍是 Web 产品，不是新增原生 App。

## Product Purpose

让商家核对营业状况、查询与管理订单记录，并管理已有菜品、桌台、经营设置、员工账号和打印配置。用户最新明确：接单统一由独立收银端执行，商家后台不再承担接单工作台。成功意味着从摘要进入正确明细并完成管理操作，返回时不丢失查询上下文。

## Operating Context

只记录 apps/merchant-admin 的商家范围，不约束同应用中的平台后台，也不改独立 Cashier 或 MiniApp。电脑、手机浏览器与主屏幕独立窗口均须可用。用户先认可 V2.1 手机外观，随后进一步要求两端首页都直接承载经营分析。手机最新导航明确为：首页 / 菜品 / 订单 / 结账 / 更多；“结账”已澄清为查看结账与收款记录，不执行收银操作。电脑版 V2.2 已获认可；手机首页已明确要求完整承载经营分析，并授权直接开发、无需再次图稿审核。设计认可不等于本地 / 真机验收；开发完成仍先本地全面验收，不提交或部署。

## Capabilities and Constraints

- 既有八模块及其查询、管理、编辑、确认、空态、错误、无权限状态保留；接单入口与接单工作台按用户最新要求从商家后台退出，收银端原有实现不改。
- Vue 3、Vite、TypeScript、Pinia；不引入 React / Next.js / React Native 或替换 API。
- OWNER / MANAGER / STAFF 及既有能力开关仍决定访问和操作权限。
- 金额为 VND 整数；显示时区 Asia/Ho_Chi_Minh。堂食按开台所属营业日，自取 / 配送按下单所属营业日。实际支付时间单独保留；不改取消、退空、作废排除口径。
- 原订单与结账单是不同对象；不存在正确数据来源的指标不伪装为可钻取。
- 不新增仓库、薪资、CRM、独立支付凭证、多计量单位等参考产品功能。
- 不因 UI 试验执行生产保存、删除、收款、打印、开通或权限修改。
- 本地验收数据环境须明确标识并隔离生产写操作；真实业务接口测试与模拟界面测试分开报告。

## Brand Commitments

首页直接使用此前线上正式「经营分析」页，桌面与手机保持同一套完整内容，不再重新设计其图表。其他页面以 KiotViet 的信息架构和操作效率为参考，并采用接近 Apple 工具型产品的安静层级、系统字体、连续列表和逐层详情；不把旧 YunQiao 后台布局当作限制。全局颜色取自正式经营分析：浅灰绿页面、近白内容区、深绿文字与小面积操作绿。保留 YunQiao 名称，不复制 KiotViet 商标，也不添加本项目不存在的功能。

## Product Principles

- 先保证业务含义和操作结果，再优化呈现。
- 摘要与明细同口径；返回与关闭不丢失工作上下文。
- 手机独立窗口是正式使用场景，不是桌面缩小版。
- 保持真实状态，区分无数据、失败、未开通与不可用。
- 本地验收、自动化通过、真机通过和生产发布分别记录。

## Accessibility & Inclusion

保留中文、越文、英文；支持长名称、长编号和大金额。检查键盘、焦点、触控目标、减少动态、安全区域和软键盘遮挡；1440 / 1280 / 1024 / 768 / 390 为目标检查宽度。
