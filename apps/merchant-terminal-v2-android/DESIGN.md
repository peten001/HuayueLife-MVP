# Design System: YunQiao Merchant Terminal V2

## Overview

**Creative North Star: "Pixel-Locked YunQiao Operations Surface"**

This is a seed record for a fixed visual authority, not permission to invent a new visual world. Each native printer screen must inherit its composition, density, language hierarchy, and control treatment from the matching individual reference PNG. Where references disagree slightly, the implementation records the discrepancy and follows the screen-specific source rather than silently averaging it.

**Key Characteristics:**

- Dense, task-led merchant operation screens.
- Existing dark Web Cashier remains visible wherever the reference shows it.
- Light native panels and white cards carry the printer workflow.
- YunQiao green communicates primary action and healthy state; orange and red remain status-specific.
- Decoration never competes with printer identity, connection state, or the next required action.

## Colors

Use only colors measured from the individual source PNG for the screen being implemented. Exact production tokens are provisional until the first screenshot-calibrated build is complete.

**The Per-Screen Authority Rule.** If nominal greens or neutrals differ between reference files, preserve the matching screen's measured value and document it; do not create an unsupported blended palette.

## Typography

Use the Android system sans-serif stack with the sizes, weights, line heights, and wrapping measured from each reference screen. Do not package or distribute a font file.

**The No-Reflow Rule.** On the D2 baseline, headings, labels, helper text, and buttons must preserve the reference line count and hierarchy; translated compact layouts may reflow only to avoid truncation or overlap.

## Layout

D2 at 1366x768 landscape is the strict pixel baseline, derived from 1672x941 references at approximately 0.817 horizontal and 0.816 vertical scale. Native-region critical geometry must remain within 4 px of the scaled reference. D10 Pro keeps the same information hierarchy at 1280x800. Compact P10 becomes a full-screen, single-column native surface with bottom actions rather than a shrunken desktop composition.

Dynamic Web merchant name, table counts, time, and order state may be masked in comparison; no native surface may be masked.

## Elevation & Depth

Use only the borders, tonal separation, dim scrims, and restrained shadows visible in the matching PNG. Cards remain quiet; modal and overlay elevation exists to separate the current task from the live cashier, not to introduce decorative depth.

## Shapes

Panel, card, field, button, status pill, and modal radii are extracted from their matching PNG and kept screen-specific until scan mode records the settled tokens. Do not substitute Material defaults when their silhouette differs from the source.

## Do's and Don'ts

### Do:

- **Do** treat `00_REAL_WEB_CASHIER_CURRENT.png` and `01_ENTRY_FLOW_REFERENCE.png` as background and entry evidence, never as Android reconstruction targets.
- **Do** implement screens `02` through `09` from their individual PNGs and retain screenshot/diff evidence for every D2 native region.
- **Do** extend the connection-choice screen with the required Classic Bluetooth option using the same measured card grammar because the `04` image visibly omits that mandated third option while its manifest and the `08` screen require it.
- **Do** keep printer business enablement visually read-only and direct changes to Merchant Admin.

### Don't:

- **Don't** add diagnostics, hidden entries, log export, service or auto-print switches, menu-category routing, decorative illustrations, gradients, or motion not present in the references.
- **Don't** normalize small reference differences without recording the chosen source value.
- **Don't** claim emulator or fake-transport output as real printer or visible-paper evidence.
